# SKILL: analyze-diff

## ROLE
변경된 코드(diff)를 빠르게 분석하고,
어떤 기능/문서/운영 영향이 생기는지 정리한다.

---

## INPUT
- git diff
- 변경 파일 목록
- commit 내용
- 관련 요청사항

---

## TASK

코드 변경을 보고 아래를 정리한다.

1. 변경 유형
- 기능 추가 / 수정 / 리팩토링 / 삭제 / 설정 변경

2. 직접 영향
- 어떤 파일/모듈/함수에 영향이 있는가

3. 간접 영향
- 문서 수정 필요 여부
- 테스트 영향
- 배포/운영 영향

4. 핵심 변화 요약
- 구조적으로 무엇이 달라졌는가

5. 리스크
- 기존 동작이 깨질 수 있는 부분
- 확인이 필요한 포인트

---

## OUTPUT FORMAT

### 변경 요약
- 유형:
- 핵심 파일:
- 목적:

### 직접 영향
- 파일:
- 변경 내용:

### 간접 영향
- 문서 영향:
- 운영 영향:
- 테스트 영향:

### 리스크
- 항목:
- 이유:

### 권장 후속 작업
- 1.
- 2.
- 3.

---

## RULES

- 코드에 없는 내용 추측 금지
- diff에 드러난 범위 중심으로만 말할 것
- “문서 갱신 필요” 여부를 항상 같이 판단할 것
