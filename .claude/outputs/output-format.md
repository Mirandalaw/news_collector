# OUTPUT FORMAT

모든 작업 결과는 아래 형식을 따른다.

응답은 불필요하게 길게 늘어놓지 말고,  
현재 단계에서 필요한 정보만 명확하게 정리한다.

---

## 1. 변경 파일

이번 작업에서 생성하거나 수정한 파일을 목록으로 적는다.

예시:
- `app/jobs/cleanup_job.py`

---

## 2. 구현 내용 요약

이번 단계에서 실제로 무엇을 추가하거나 구성했는지 간단히 설명한다.

포함해야 할 내용:
- 어떤 구조를 만들었는지
- 어떤 함수/흐름을 추가했는지
- 기존 어떤 패턴을 따랐는지

설명은 짧고 명확하게 작성한다.

---

## 3. 주의사항

이번 단계에서 **아직 하지 않은 것**과  
다음 단계에서 해야 할 것을 분리해서 적는다.

포함 예시:
- 아직 DELETE SQL은 구현하지 않음
- dry-run 로직은 다음 단계에서 구현 예정
- batch delete는 다음 단계에서 추가 예정

---

## 4. 코드

사용자가 전체 코드를 요청한 경우:
- 요청한 파일의 전체 코드를 제공한다

사용자가 특정 수정만 요청한 경우:
- 변경된 부분만 제공한다

현재 단계가 새 파일 생성이라면:
- 전체 파일 코드를 제공하는 것을 기본으로 한다

---

## 5. 선택 사항: 검증 포인트

필요할 경우 아래 내용을 추가할 수 있다.

- 실행 시 확인해야 할 점
- 다음 단계에서 검증할 항목
- 예상 동작 방식

단, 불필요하게 길게 쓰지 않는다.

---

## 응답 규칙

1. 현재 단계 범위를 벗어난 설명을 하지 않는다
2. 구현하지 않은 기능을 구현한 것처럼 쓰지 않는다
3. 추측성 설명을 하지 않는다
4. 결과 요약 → 주의사항 → 코드 순서를 유지한다
5. 가능하면 리뷰하기 쉽게 섹션을 분리한다

---

## 금지사항

- 장황한 배경 설명
- 요구하지 않은 추가 설계 설명
- 여러 대안을 길게 비교하는 응답
- 현재 단계와 무관한 코드 제안
