# PROJECT OVERVIEW

## 프로젝트명
뉴스 수집 및 아침 브리핑 자동화 시스템

---

## 프로젝트 목적

여러 뉴스 소스에서 기사를 수집하고,  
중복과 노이즈를 줄인 뒤,  
핵심 내용만 정리한 아침 브리핑을 자동 생성하는 것이 목적이다.

이 시스템은 단순 기사 나열이 아니라,  
사용자가 아침에 빠르게 시장 상황과 주요 종목 이슈를 파악할 수 있는  
**읽기 쉬운 투자 보조 브리핑**을 만드는 것을 목표로 한다.

---

## 프로젝트 범위

이 프로젝트는 아래 흐름을 다룬다.

1. 뉴스 수집
2. 기사 분류
3. 중복 제거 및 품질 보정
4. 브리핑 생성
5. 메신저 전송
6. 로그 기록 및 운영 관리

---

## 핵심 문제

기본 뉴스 수집만으로는 아래 문제가 발생한다.

1. 같은 내용이 여러 기사로 반복된다
2. 중요하지 않은 기사가 브리핑에 섞인다
3. 카테고리 분류 품질이 일정하지 않다
4. event 같은 특정 섹션이 비거나 과하게 채워질 수 있다
5. cron / 배포 / 권한 문제로 실행이 끊길 수 있다
6. 데이터가 계속 누적되지만 정리 정책이 없으면 운영 부담이 커진다

---

## 현재 시스템이 해결해야 하는 것

1. 안정적 수집
2. 중복 기사 제거
3. 브리핑 품질 개선
4. 메신저 전송 안정성 확보
5. 로그 기반 운영 안정화
6. 데이터 보존 및 정리 정책 수립

---

## 현재까지 구현된 상태

현재 시스템은 아래 수준까지 진행되었다.

- RSS 기반 뉴스 수집 구조 존재
- DB 저장 구조 존재
- cron 기반 실행 구조 존재
- 브리핑 builder / renderer 구조 존재
- dedup 1차 적용 완료
- signal 출력 연결 완료
- event 섹션 builder 레이어 보강 완료
- event classifier 1차 보정 완료
- cleanup / retention은 설계 단계이며 구현 예정

즉, 현재 위치는  
**MVP 구현 완료 후 품질 고도화 및 운영 안정화 단계**이다.

---

## 현재 고도화 단계의 핵심 목표

현재 단계에서 가장 중요한 목표는 아래와 같다.

1. 브리핑 품질 안정화
2. event 섹션 품질 검증 및 마무리
3. cleanup / retention 구현
4. dedup 2차 설계 준비
5. 운영 관점의 유지보수성 강화

---

## 주요 관심사

### 제품 관점
- 아침에 바로 읽을 수 있는 수준의 브리핑
- 반복 없는 요약
- 카테고리 균형
- event / market / symbol 섹션의 역할 분리
- 너무 긴 출력 방지
- 중요 기사 우선 노출

### 엔지니어링 관점
- 작업 단위 분리
- 재실행 가능성
- 장애 원인 추적 가능성
- 기존 구조를 해치지 않는 개선
- 유지보수 가능한 구조
- 운영 명령의 단순화

---

## 우선순위

현재 우선순위는 아래와 같다.

1. 뉴스 브리핑 품질 개선
2. event 섹션 안정화
3. 운영 자동화 안정성 확보
4. 데이터베이스 보존/정리 정책 수립 및 구현
5. 중복 기사 필터링 고도화

---

## 작업 판단 기준

좋은 변경의 기준:
- 브리핑 품질이 올라간다
- 중복 노출이 줄어든다
- event / market / symbol 구분이 더 자연스러워진다
- 장애 추적이 쉬워진다
- 운영 명령이 단순해진다
- 변경 범위 대비 효과가 크다
- 기존 구조를 크게 흔들지 않는다

좋지 않은 변경의 기준:
- 출력 품질 개선 없이 구조만 복잡해진다
- 과도한 리팩토링이 발생한다
- 운영 경로가 늘어나고 디버깅이 어려워진다
- 현재 필요하지 않은 확장성까지 미리 넣는다
- 한 번의 변경으로 여러 레이어를 동시에 흔든다

---

## 이번 프로젝트에서 우선하는 원칙

1. 작은 변경으로 큰 효과를 낸다
2. 기존 구조를 가능한 한 유지한다
3. 먼저 검증 가능한 것부터 개선한다
4. 운영 안정성을 기능 확장보다 우선한다
5. 추측보다 로그와 출력 결과를 기준으로 판단한다
