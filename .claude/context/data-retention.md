# DATA RETENTION CONTEXT

## 목표
뉴스/요약/브리핑/로그 데이터의 보존 기준을 정하고 cleanup 작업 기준을 수립한다.

---

## 왜 필요한가

1. 뉴스 데이터는 지속적으로 누적된다
2. 오래된 데이터는 현재 브리핑 품질에 직접 기여하지 않을 수 있다
3. 중복 비교 비용과 조회 범위가 커질 수 있다
4. 운영 비용과 장애 가능성이 증가한다

---

## 관리 대상

### article
원문성 뉴스 데이터

### summary
기사 요약 또는 후처리 결과

### briefing
최종 생성된 브리핑 결과물

### log
수집, 배포, 브리핑 생성, 운영 관련 로그

---

## 기본 원칙

1. 재생성 가능한 데이터는 짧게 보관 가능
2. 원문성 데이터는 비교적 길게 보관
3. 운영 로그는 짧게 보관하되 장애 추적 가능 기간은 확보
4. 삭제 전 archive 필요 여부를 먼저 판단
5. cleanup은 수동이 아니라 job/cron 기반으로 자동화하는 것을 목표로 한다

---

## 검토 포인트

1. 어떤 데이터가 재생성 가능한가
2. 어떤 데이터가 운영 감사/품질 비교에 필요한가
3. 어떤 데이터가 dedup 기준으로 필요한가
4. 삭제보다 archive가 더 적합한 데이터는 무엇인가
