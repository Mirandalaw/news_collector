# CONSTRAINTS

## 목적

이 문서는 코드 구현 시 지켜야 할 제약 조건을 정의한다.

목표는 다음과 같다.

- 불필요한 설계 확장을 방지한다
- 기존 구조를 유지한다
- 작업 범위를 명확히 제한한다
- Claude가 추측으로 기능을 추가하는 것을 막는다

---

## 공통 원칙

1. 요구된 작업만 수행한다
2. 추측 기반 구현을 하지 않는다
3. 불필요한 기능 추가를 하지 않는다
4. 기존 코드 스타일과 구조를 우선 따른다
5. 최소 변경으로 목적을 달성한다

---

## 구조 유지 원칙

현재 프로젝트는 다음 구조를 기준으로 동작한다.

- job 단위 실행 구조 (`collect_job.py`, `briefing_job.py`)
- `setup_job_logging` 기반 로그 처리
- `JobResult` 반환 구조
- `try_record_job_run` 기반 실행 기록

### 반드시 지켜야 할 것

- cleanup job도 위 구조를 그대로 따른다
- 새로운 실행 구조를 만들지 않는다
- 기존 job 패턴을 변경하지 않는다

---

## 이번 작업 범위 제한 (cleanup 기준)

현재 작업은 **cleanup 기능 구현**에 한정된다.

### 허용되는 작업

- `cleanup_job.py` 생성
- CLI 인자 추가 (`--dry-run`, `--target`)
- dry-run 구현
- batch delete 구현
- logging 및 job_metrics 기록 연결

---

### 금지되는 작업

아래 작업은 이번 단계에서 절대 수행하지 않는다.

#### 구조 변경
- 다른 job 파일 수정 (`collect_job.py`, `briefing_job.py`)
- builder / renderer 수정
- DB 스키마 변경

#### 기능 확장
- archive 기능 추가
- 다중 보존 정책 시스템 도입
- 설정 파일 분리 (env/config)
- 관리자 UI 또는 관리 API 추가

#### 설계 확장
- 공용 유틸 과도하게 생성
- 추상화 레이어 추가
- 범용 cleanup 프레임워크 구축

---

## 데이터 관련 제약

- retention 정책은 `data-retention.md`를 따른다
- 보존 기간은 코드에서 임의 변경하지 않는다
- DELETE 대상 조건을 확장하지 않는다
- cleanup 범위를 명시된 테이블로 제한한다

---

## 구현 방식 제약

### dry-run
- 반드시 지원해야 한다
- 실제 DELETE를 실행하면 안 된다

### batch delete
- 대량 DELETE를 한 번에 실행하지 않는다
- batch 단위로 나누어 처리한다

### logging
- 기존 `setup_job_logging` 사용
- 별도의 logging 시스템 추가 금지

### 실행 기록
- `try_record_job_run` 패턴 사용
- job_metrics 구조를 변경하지 않는다

---

## 코드 작성 원칙

1. 한 번에 한 기능만 구현한다
2. 단계별로 구현한다 (구조 → dry-run → delete)
3. 테스트 가능한 단위로 작성한다
4. 과도한 예외 처리 추가하지 않는다
5. 불필요한 최적화는 하지 않는다

---

## 금지된 행동

아래는 명시적으로 금지한다.

- 요구되지 않은 기능 추가
- 기존 코드 리팩토링
- 파일 구조 변경
- 설정 시스템 변경
- 새로운 dependency 추가
- 코드 스타일 임의 변경

---

## 우선순위 기준

구현 시 아래 기준을 따른다.

1. 안정성
2. 단순성
3. 기존 구조 유지
4. 확장성 (후순위)

---

## 판단 기준

어떤 구현이 맞는지 판단이 필요할 경우 아래 기준을 따른다.

- 더 단순한 방법을 선택한다
- 기존 코드와 일관된 방식을 선택한다
- 변경 범위가 작은 방법을 선택한다
- 운영자가 이해하기 쉬운 방법을 선택한다

---

## 실패 방지 원칙

cleanup은 데이터 삭제를 포함하므로 아래를 반드시 지킨다.

1. dry-run 먼저 구현한다
2. 실제 삭제는 그 다음 단계에서 구현한다
3. 한 번에 대량 삭제하지 않는다
4. 삭제 기준은 명확하게 유지한다

---

## 현재 단계 상태

- cleanup 기능: 미구현
- retention 정책: 정의 완료
- 현재 작업: cleanup 설계 및 구현 준비 단계

---

## 이 문서의 역할

이 문서는 다음을 보장한다.

- Claude가 불필요한 기능을 추가하지 않는다
- 작업 범위가 명확하게 유지된다
- 구현 방향이 일관되게 유지된다
