# TRADE CANDIDATE VALIDATION

## 목적

뉴스 기반 매매 후보 시스템의 실제 성능을 검증한다.

현재 시스템은 다음 단계를 모두 통과한 상태다.

- signal 생성
- scoring
- aggregation
- decision
- price filter
- trade candidate output
- briefing 연결

이 단계에서는 기능 추가가 아니라,
**후보 품질을 검증하고 개선 포인트를 도출하는 것**이 목적이다.

---

## 검증 목표

1. 후보 개수 적정성
2. 후보 이유 타당성
3. false positive (잘못된 후보) 식별
4. false negative (놓친 기회) 식별
5. 다음 조정 포인트 1개 도출

---

## 검증 기준

### 1. 후보 개수

- 이상적: 0~3개
- 5개 이상: 과도 (조건 느슨)
- 0개 지속: 조건 과도하게 엄격

---

### 2. 후보 이유 타당성

각 후보에 대해 확인:

- 뉴스 내용과 signal 방향이 일치하는가
- price filter 조건이 실제 데이터와 맞는가
- reason 문구가 납득 가능한가

---

### 3. false positive

정의:
- 실제로는 매수/매도하면 안 되는 후보

예:
- 단순 기사인데 signal 발생
- 가격 조건만 맞고 의미 없는 종목

---

### 4. false negative

정의:
- 실제 기회였는데 후보에 포함되지 않은 경우

예:
- 강한 뉴스인데 signal 미발동
- price filter에서 과도하게 걸림

---

## 기록 포맷

검증은 아래 구조로 기록한다.

### 예시

- 날짜: 2026-04-12
- 종목: 005930
- 판단: buy_candidate
- 결과: false positive
- 이유: 뉴스는 중립인데 price 조건만 통과

또는

- 날짜: 2026-04-12
- 종목: 000660
- 판단: 없음
- 결과: false negative
- 이유: 실적 서프라이즈 뉴스 있었지만 signal 미발동

---

## 분석 기준

다음 질문에 답할 수 있어야 한다.

1. 후보는 적절한 개수인가?
2. 후보는 논리적으로 설명 가능한가?
3. 반복되는 오탐 패턴이 있는가?
4. 반복되는 미탐 패턴이 있는가?

---

## 출력 목표

이 단계의 최종 결과는:

- 개선 포인트 1개

예:
- threshold 조정
- 특정 키워드 보강
- symbol noise 필터 수정
- price filter 조건 수정

---

## 금지사항

- 새로운 기능 추가
- 규칙 대량 추가
- 기술지표 확장
- 자동매매 연결
- 구조 변경

---

## 설계 원칙

1. 데이터 기반 판단
2. 단일 개선 포인트만 선택
3. 과도한 수정 금지
4. 재현 가능한 분석 유지
