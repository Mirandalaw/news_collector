# DEDUP V2 DESIGN

## 목적

같은 이슈를 다루는 서로 다른 제목의 기사들을 묶어  
브리핑에서 중복 노출을 줄이고 품질을 개선한다.

현재는 URL / title_hash 기반의 1차 dedup만 적용되어 있으며,  
동일 이슈라도 제목이 다르면 중복으로 출력되는 문제가 있다.

---

## 현재 한계

현재 dedup 방식:

- URL unique constraint
- title_hash 기반 동일 제목 제거

문제:

1. 같은 이슈라도 제목이 다르면 중복으로 노출됨
2. 언론사별 표현 차이로 동일 기사 다수 발생
3. 브리핑 가독성 저하
4. signal / event 해석 중복 발생

---

## 목표

1. 동일 이슈의 기사들을 하나의 그룹으로 묶는다
2. 대표 기사 1개만 브리핑에 노출한다
3. 오탐(다른 이슈를 묶는 것)을 최소화한다
4. 기존 dedup v1 위에 "보수적으로" 추가 적용한다

---

## 적용 위치

dedup v2는 builder 레이어에서 적용한다.

- DB 변경 없음
- collector 변경 없음
- builder 내부에서 그룹핑 처리

적용 대상:

- market_section
- symbol_section

event_section은 현재 단계에서 제외

---

## 후보 방식

### 1. normalize_title

목적:
- 비교 가능한 형태로 제목 정규화

처리:

- 소문자 변환
- 특수문자 제거
- 불필요 단어 제거 (예: "속보", "단독", "오늘의", "전망")

---

### 2. keyword overlap

목적:
- 핵심 키워드 기반 유사도 판단

방식:

- 제목을 단어 리스트로 분해
- 공통 키워드 개수 계산

---

### 3. Jaccard similarity

목적:
- 두 제목 간 유사도 수치화

공식:
유사도 = 교집합 / 합집합


---

## MVP 설계

초기 버전은 단순하게 시작한다.

### 기준

- normalize_title 적용
- 단어 분해 후 set 생성
- Jaccard similarity 계산

### threshold

- 기본값: 0.6

조건:

- similarity >= 0.6 → 동일 그룹으로 판단

---

## 그룹 처리 방식

1. 기사 리스트 순회
2. 이미 그룹에 포함된 기사인지 확인
3. 기존 그룹과 유사도 비교
4. 가장 유사한 그룹에 추가
5. 없으면 새로운 그룹 생성

---

## 대표 기사 선택 기준

각 그룹에서 하나만 선택

우선순위:

1. signal 존재 기사
2. 제목 길이 (정보량)
3. 최신 시간

---

## 제외 조건 (중요)

아래 경우는 절대 묶지 않는다.

1. 종목 코드가 다른 경우
2. event_type이 다른 경우
3. signal 방향이 반대인 경우 (bullish vs bearish)

---

## 출력 정책

- 그룹당 1개 기사만 출력
- 나머지는 제거
- 필요 시 "(외 N건)" 표시 (추후 고려)

---

## 오탐 방지 원칙

1. threshold를 낮추지 않는다
2. 애매하면 묶지 않는다
3. 다른 이슈를 묶는 것보다 중복을 허용하는 것이 낫다

---

## 이번 단계 범위

- builder 내부 그룹핑 적용

제외:

## 검증 기준

1. 동일 이슈 기사 수 감소
2. 다른 이슈가 묶이지 않음
3. 브리핑 가독성 개선
4. event / signal 영향 없음

## 현재 결론

dedup v2는 표면 유사도가 높은 기사들을 보수적으로 묶는 방식으로 유지한다.

현재 구조는:
- URL / title_hash보다 한 단계 확장된 dedup
- 그러나 의미 유사도 전체를 해결하는 시스템은 아님

한영 혼용, 동의어, 문장 의미 차이까지 포괄하려면
현재 Jaccard 기반 구조를 넘어서는 복잡도가 필요하므로
이번 단계에서는 여기서 마무리한다.
